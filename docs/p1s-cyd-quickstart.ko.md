# P1S Cloud용 XTouch CYD 테스트 빌드

대상은 기존 XTouch의 2.8인치 CYD(ESP32-2432S028R, ESP32, ILI9341 계열 화면과 XPT2046 터치)입니다. ESP32-C3/S3용 이미지가 아닙니다.

## Bambu Lab 계정으로 설정 (SD 없이, 권장)

`0.9.213-cyd.2`부터 Wi-Fi, Cloud 설정, 화면 설정과 터치 보정값을 보드 내부 플래시에 저장합니다. SD 카드는 필요하지 않습니다.

`0.9.213-cyd.6` 패키지에는 ha-bambulab의 로그인 절차를 참고한 PC 설정 도구가 포함됩니다. 기존 `cyd.2` 펌웨어의 USB 설정과도 호환됩니다. `cyd.4`의 Cloud 수신 수정, `cyd.5`의 P1 필라멘트·AMS 수정에 더해 조명 상태 처리와 USB 진단을 개선했습니다. `cyd.6` 실물 설치와 USB 명령에 따른 조명 끄기·켜기의 프린터 상태 보고를 확인했습니다. 사용자도 화면 터치로 실제 조명이 바뀜을 확인했으며 반응 지연을 보고했습니다.

1. 보드를 USB로 PC에 연결합니다. Python 3.10 이상이 필요하며, 처음에는 패키지 폴더에서 `python -m pip install -r scripts/setup-requirements.txt`를 실행합니다.
2. Windows에서는 `start-setup.cmd`를 실행합니다. 다른 환경에서는 `python scripts/setup-server.py --open`을 실행합니다. Chrome/Edge에서 **http://127.0.0.1:8767**을 엽니다. 소스 작업 폴더에서도 같은 명령을 사용할 수 있습니다.
3. **USB 보드 연결**을 누르고 CH340(CYD) 포트를 선택합니다. 버튼 아래에 **USB 연결됨**과 펌웨어 버전이 표시되는지 확인합니다. 다른 XTouch 설정 탭이나 시리얼 모니터가 포트를 사용 중이면 먼저 닫거나 **USB 연결 해제**를 누릅니다. 케이블을 꽂는 것과 브라우저에서 포트를 선택하는 것은 별도입니다. USB 연결 없이 저장을 누르면 보드 선택창부터 열립니다.
4. 보드가 사용할 **2.4GHz Wi-Fi 이름과 비밀번호**를 입력합니다.
5. 연결 방식은 **Bambu Lab 계정 로그인**으로 두고 계정 지역을 선택합니다. 이메일과 Bambu Lab 비밀번호를 입력한 뒤 **Bambu Lab 로그인**을 누릅니다. 비밀번호 없는 소셜 로그인은 지원하지 않습니다.
6. 요청되면 이메일 인증 코드 또는 인증 앱의 2단계 인증 코드를 입력합니다. 이메일이 오지 않으면 **이메일 코드 다시 받기**를 누릅니다. 입력한 계정을 바꾸려면 **로그인 다시 시작**을 누릅니다.
7. **내 프린터**에서 P1S를 선택하고 **보드에 저장하고 재시작**을 누릅니다. 지원 프린터가 한 대면 자동으로 선택됩니다.
8. 처음 연결하면 보드 화면의 `+` 표시 두 곳을 차례로 눌러 터치를 보정합니다. 보정값도 내부에 남습니다. 설정 도구를 종료하고 USB 전원만 공급해도 보드는 독립적으로 Cloud에 연결합니다.

계정 비밀번호는 Bambu 로그인 요청에만 사용하고 보드나 파일에 저장하지 않습니다. PC 설정 도구는 로그인 세션을 메모리에 보관하며, 마지막 사용 후 1시간이 지나거나 도구를 종료하면 지웁니다. 그 실행 중에는 **이번 실행에서 로그인한 계정**에서 이메일을 선택해 다른 보드나 프린터 설정에 재사용할 수 있습니다. Home Assistant에 저장된 계정을 자동으로 가져오는 기능은 아닙니다. 보드에는 Wi-Fi 설정과 선택한 프린터의 Cloud 토큰이 저장됩니다.

CH340 보드는 브라우저에서 USB 포트를 열 때 재부팅될 수 있습니다. 설정 도구는 부팅 중 손실된 상태 조회 명령을 다시 보내며 최대 35초 동안 응답을 기다립니다. **보드가 재시작했습니다** 안내가 나오면 연결 버튼을 반복해서 누르지 말고 **USB 연결됨** 표시를 기다립니다.

이전 안내의 `python -m http.server`는 이메일 로그인 API를 제공하지 않습니다. 새 로그인 화면을 쓰려면 위의 `setup-server.py`를 실행해야 합니다.

Python/pyserial을 사용하는 경우, 설정 파일을 PC에 둔 채 `python scripts/provision-usb.py --port COM7 --config xtouch.json`으로 전송할 수도 있습니다. `--config`를 생략하면 상태를 읽습니다. `--validate-only`는 저장 없이 입력을 검증합니다.

## LAN 수동 연결 또는 기존 Cloud 토큰 사용

같은 설정 화면의 **연결 방식**에서 **LAN 수동 연결**을 선택하면 Bambu 계정 로그인 없이 프린터 IP, 8자리 LAN access code, 시리얼 번호와 모델을 입력할 수 있습니다. 보드와 프린터가 통신할 수 있는 같은 LAN을 사용합니다. 프린터 펌웨어의 LAN 제어 허용 설정도 확인해야 합니다.

이미 가진 Cloud 인증정보를 쓰려면 **Cloud 토큰 직접 입력 (고급)**을 선택하고 사용자명 `u_...`, 토큰, 계정 지역, 프린터 시리얼과 모델을 입력합니다. 토큰이 JWT이면 사용자명을 비워도 됩니다.

## SD 없이 휴대폰으로 설정

설정이 없거나 Wi-Fi 연결이 20초 동안 실패하면 보드가 `XTouch-Setup-XXXX` Wi-Fi를 만듭니다. 화면에 표시된 임시 비밀번호로 접속하고 **http://192.168.4.1**을 열어 값을 입력합니다. 임시 비밀번호는 재부팅마다 바뀝니다. 인터넷이 없는 Wi-Fi라는 안내가 나오면 연결을 유지합니다.

보드가 제공하는 이 페이지에서는 **LAN 수동 연결** 또는 **Cloud 토큰 직접 입력**을 사용합니다. 이메일·비밀번호 로그인은 위의 PC 설정 도구에서 처리합니다.

저장 후 보드가 재시작하면 휴대폰을 원래 Wi-Fi로 돌립니다. 저장한 Wi-Fi에 접속하면 설정용 AP는 열리지 않습니다. USB의 `python scripts/provision-usb.py --port COM7 --setup`으로 다시 설정 모드에 들어갈 수 있습니다.

## 기존 XTouch에서 SD로 업데이트

1. SD 카드의 기존 내용을 백업합니다.
2. 이 패키지의 `xtouch28` 폴더를 Chrome/Brave 확장 관리 화면에서 **개발자 모드 → 압축해제된 확장 프로그램 로드**로 엽니다.
3. 확장 프로그램에 2.4GHz WiFi SSID·비밀번호, P1S 시리얼, 모델 `P1S`를 입력합니다.
4. HA의 ha-bambulab에서 사용하는 Cloud `username`과 `auth_token`을 입력합니다. 사용자명은 `u_...`입니다. Global/China는 해당 Bambu 계정 지역을 선택합니다. 토큰이 JWT이면 사용자명이 자동으로 채워질 수 있습니다.
5. **Download xtouch.json**을 누릅니다. IP 입력은 SD 다운로드에 필요하지 않습니다. 파일에는 인증정보가 들어 있으므로 개인 SD 카드에서 관리합니다.
6. SD 카드에 `/xtouch/ota.json`이 남아 있으면 백업한 뒤 그 파일만 삭제합니다. 이전 OTA의 MD5 값이 새 수동 업데이트를 거부하지 않도록 하는 절차입니다. `/xtouch/`의 나머지 설정 파일은 유지합니다.
7. SD 카드 루트에 새 `xtouch.json`과 패키지의 `firmware.bin`을 복사하고 CYD를 재부팅합니다. `xtouch-cyd-full.bin`은 SD 업데이트용이 아닙니다.

내부 설정이 아직 없을 때만 SD 설정을 가져옵니다. 이후 값 변경은 USB 또는 웹 설정 화면에서 합니다. SD를 넣지 않아도 정상 사용합니다.

확장 없이 `xtouch-p1s-cloud.example.json`의 예시 값을 바꾸고 이름을 `xtouch.json`으로 저장해도 됩니다. `authToken`에는 WiFi 비밀번호나 프린터 LAN access code가 아닌 Bambu 계정의 Cloud 토큰을 넣습니다. HA는 실행 중이지 않아도 되며 CYD가 Cloud MQTT에 직접 연결합니다.

`Read login from current Bambu tab`은 로그인된 Bambu 웹 탭의 토큰을 읽는 보조 기능입니다. 사이트 구조에 따라 사용자명을 읽지 못하면 HA의 값을 직접 입력합니다. 확장 프로그램은 토큰과 WiFi 비밀번호를 브라우저 저장소에 보관하지 않습니다.

## USB로 설치할 때

소스가 있는 PC에서는 보드를 연결하고 정확한 포트를 선택해 실행합니다.

```powershell
pio run -e esp32dev -t upload --upload-port COM번호
pio device monitor --port COM번호 --baud 115200
```

독립 패키지를 쓰는 경우, esptool이 설치된 Python에서 다음과 같이 **확인된 CYD 포트**에 기록할 수 있습니다.

```powershell
python -m esptool --chip esp32 --port COM번호 --baud 460800 write_flash 0x0 xtouch-cyd-full.bin
```

전체 USB 이미지는 부트로더, 파티션, OTA 부트 정보와 앱을 포함하며 플래시의 기존 NVS 영역도 덮어씁니다. 이미 이 CYD 리비전을 설치했고 파티션 구성이 같다면 `firmware.bin`만 앱 영역 `0x10000`에 기록해 설정을 유지할 수 있습니다. 보드를 초기 설치할 때는 전체 이미지를 사용합니다.

## 연결 확인

프린터도 같은 Bambu 계정의 Cloud에 연결돼 있어야 합니다. CYD는 WiFi 연결 뒤 NTP 시각 동기화, TLS 연결, MQTT 인증과 구독 순으로 진행합니다. NTP는 UDP 123, MQTT는 TCP 8883을 사용합니다.

115200bps 시리얼 로그에서 다음 순서를 확인합니다.

```text
[XTouch] CYD Cloud revision 0.9.213-cyd.5
[XTouch][MQTT] Connected; subscription sent to device/<serial>/report
[XTouch][MQTT] Printer push_status received
```

첫 번째 상태 보고가 들어오면 홈 화면으로 전환합니다. `cyd.4`를 실제 CYD에 설치해 P1S Cloud 상태 수신, 노즐·베드 온도 갱신과 홈 화면 상태를 USB로 확인했습니다. 프린터 제어 명령 수행은 아직 검증하지 않았습니다.

USB에서 `XTOUCH STATUS`를 보내면 `mqtt_connected`와 `printer_status_received`를 별도로 확인할 수 있습니다. 상태를 받았다면 마지막 수신 후 경과 시간 `status_age_ms`, 노즐·베드 온도도 반환합니다. `screen_index`가 `0`이면 홈 화면, `-1`이면 시작·설정 화면입니다. 이 응답은 저장된 Wi-Fi 비밀번호나 Cloud 토큰을 반환하지 않습니다.

## HA와 제어 방식 비교

### cyd.6 조명 진단 수정본

2026-09-27 조명 무반응 보고 후 수정하고 실제 CYD에 설치한 버전입니다. 전체 플래시 백업과 파티션 일치를 확인한 뒤 앱만 기록해 기존 설정을 유지했습니다. Wi-Fi·Cloud 재연결, P1S 상태 수신, USB 명령으로 조명 끄기·켜기 모두 `state_confirmed`를 확인했고 원래 켜짐 상태로 복원했습니다. 사용자도 화면 터치로 실제 조명이 바뀜을 확인했으며 반응 지연을 보고했습니다. 이전 무반응의 원인은 확정하지 못했습니다. 조명 상태는 `lights_report` 배열의 첫 항목이 아니라 `chamber_light` 노드를 찾아 읽습니다. 다른 조명만 보고된 경우 마지막 상태를 유지합니다. 버튼 표시도 클릭 즉시 바꾸지 않고 프린터 상태 보고에 따라 갱신합니다.

USB `XTOUCH STATUS`에 `mqtt_state`, `light_on`, `light_requests`, `light_target`, `light_published`, `light_result`가 추가됐습니다. `sent`는 전송 성공, `acknowledged`는 성공 응답 수신, `state_confirmed`는 요청한 상태의 보고 수신이며 각각 구분합니다. `publish_failed`와 `rejected`는 전송 실패와 명령 거부입니다. USB의 `XTOUCH LIGHT TOGGLE`은 화면 버튼과 같은 경로로 실제 조명 전환을 요청하는 진단 명령입니다.

조명, 팬, 온도, 축 이동, 압출, 출력 속도, 일시정지·재개·중지는 ha-bambulab과 같은 Cloud MQTT 명령 계열을 사용합니다. HA에서 이미 조작되는 P1S를 일괄적으로 제어 불가능한 모델로 취급하지 않습니다.

`cyd.5`는 프린터 버전을 조회해 P1 펌웨어 `01.02.99.10` 이상이면 필라멘트 넣기·빼기에 HA의 `ams_change_filament`를 사용합니다. 실제 연결된 P1S는 `01.09.00.00`을 보고했습니다. 외부 스풀을 넣을 때는 등록된 재료의 권장 온도 중간값을 사용하며, 온도 정보가 없으면 HA처럼 0을 보내 프린터에 맡깁니다. 이전 P1 펌웨어와 X1은 기존 경로를 유지합니다.

현재 CYD의 넣기 버튼은 외부 스풀용이고, 빼기 버튼은 현재 로드된 스풀을 대상으로 합니다. HA처럼 임의의 AMS 슬롯을 고르는 화면은 아직 없습니다. 슬롯 번호·AMS 동작 상태만 오는 부분 보고도 반영하며, 실제 로드 상태와 프린터·AMS 동작 상태에 따라 버튼을 갱신합니다. 명령 내용과 상태 처리의 자동 테스트는 통과했지만, 실제 가열·이동·필라멘트 교체 완료까지 검증한 것은 아닙니다.

2026-09-25에 `cyd.5`를 실제 CYD에 설정 보존 방식으로 설치했습니다. 보드에서 P1S `01.09.00.00`, 새 필라멘트 명령 지원, 현재 슬롯 255(로드된 필라멘트 없음), 넣기 가능·빼기 불가 상태와 Cloud 온도·상태 수신을 확인했습니다. 이 검증에서는 가열·축 이동·필라멘트 교체·출력 제어를 실행하지 않았습니다.

## 토큰 교체와 복구

- 설정이 빠졌거나 MQTT 인증이 거부되면 `Provision at <IP>`가 표시됩니다. PC 설정 도구에서 다시 로그인하고 USB로 새 설정을 저장합니다. 같은 LAN의 확장 프로그램에서 새 전체 설정과 그 IP를 입력해 **Provision xtouch**를 사용할 수도 있습니다. 정상 저장 응답 뒤 재부팅합니다. ESP32가 Cloud 계정 비밀번호를 보관하거나 토큰을 자동 갱신하지는 않습니다.
- 네트워크 설정 쓰기는 이 복구 화면이 활성화됐을 때만 허용합니다. 정상 연결 중에는 HTTP 409를 반환합니다.
- 새 설정은 내부 저장소의 임시 파일에 완전히 기록한 다음 교체합니다. 이전 `/xtouch.json`은 `/xtouch.json.bak`에 남고, 교체 중 전원이 끊겨 원본이 없으면 백업을 읽습니다.
- `/xtouch.json`이 `/provisioning.json`보다 우선합니다. 구형 파일을 수정했는데 반영되지 않으면 이 우선순위를 확인합니다.
- 이 리비전에서는 예전 XTouch 서버의 온라인 자동 업데이트를 끕니다. 후속 업데이트도 SD 또는 USB를 사용합니다.

## 검증 범위

ESP32 빌드, 실제 ArduinoJson 설정·메시지 버퍼 회귀 테스트, USB 보드 상태 조회·입력 검증·긴 입력 복구를 확인했습니다. 실제 보드는 SD 없이 내부 저장소와 설정 AP로 부팅했고 사용자가 화면 표시를 확인했습니다. 계정 로그인 흐름은 외부 인증 요청 없는 가짜 응답으로 이메일 코드·2단계 인증·오류·세션 만료를 테스트하고, Edge에서도 코드 입력부터 P1S 선택까지 확인했습니다. 포함된 CA로 Global/China 브로커 TLS 1.2도 검증했습니다.

2026-09-25에는 실제 계정과 온라인 P1S로 PC의 MQTT 구독 승인과 상태 보고를 확인했습니다. CYD 수신 콜백의 로그 매크로에 `else`가 잘못 결합되어 정상 보고를 건너뛰던 오류를 수정한 뒤, `cyd.4` 앱만 `0x10000`에 설치했습니다. 저장된 설정 유지, Wi-Fi·MQTT 연결, P1S 상태 수신과 홈 화면 상태를 확인했고 노즐·베드 온도도 수신했습니다. 출력 시작·정지, 축 이동·히터·팬 등 프린터 제어 명령은 이 진단에서 보내지 않았습니다. 실물 터치 조작과 제어 동작은 별도 확인이 필요합니다.

실제 Edge Web Serial에서 COM7을 열면 보드가 재부팅되는 현상을 재현했습니다. 부팅 대기와 재조회를 적용한 최종 페이지로 `cyd.2` 보드 연결 및 2,047바이트 테스트 토큰을 포함한 설정의 USB 검증 명령이 성공했습니다. 이 검증은 실제 설정을 저장하지 않습니다.
